# Finspace — образовательное мини-приложение для MAX

Проект помогает начинающим разобраться в криптовалютах без покупки реальных активов: короткие уроки и тесты ведут по учебному маршруту, кейсы учат замечать риски, а Historical Market Replay позволяет принимать решения с виртуальными деньгами. Основной сценарий: открыть бота в MAX → перейти в мини-приложение → посмотреть маршрут → пройти урок и тест → попробовать безопасную практику → увидеть прогресс.

Состав: React/Vite-интерфейс (`apps/web`), Node.js/Express API и бот MAX (`apps/api`), PostgreSQL для прогресса. В Docker интерфейс раздаётся тем же API-сервером; Compose поднимает приложение и БД. Версии npm-зависимостей закреплены в `package-lock.json`.

Раздел «Учиться» содержит 4 направления по 5 уроков. Каждый из 20 уроков разбит на 6 смысловых страниц, 2 промежуточные проверки и итоговый тест с разбором ошибок.

В практике доступны пять исторических сценариев, включая «Глобальный шок и восстановление» (2020–2021): новости открываются по мере движения исторического времени, результат сравнивается с простым планом покупки и удержания.

## Быстрый запуск без базы

```powershell
npm install
npm run dev
```

- Frontend: http://localhost:5173
- API: http://localhost:4100/api/v1/health

Без `DATABASE_URL` API использует память. Это удобно для просмотра, но прогресс сбрасывается после перезапуска backend.

## Проверка локальной версии через Docker

Нужны Git и запущенный Docker Desktop с Docker Compose v2. После клонирования репозитория из его корня выполни **одну команду** (без токенов и создания `.env`):

```powershell
docker compose up --build --wait
```

Открой http://localhost:4100. `--wait` завершится, когда оба контейнера станут `healthy`. Адрес http://localhost:4100/api/v1/health должен вернуть JSON `{"status":"ok","service":"crypto-education-api"}`. Первоначальная загрузка базовых образов и npm-пакетов требует интернета; само приложение и учебный сценарий работают без внешнего API.

| Компонент | Адрес на компьютере | В сети Compose |
| --- | --- | --- |
| Интерфейс и API | `127.0.0.1:4100` | `app:4100` |
| PostgreSQL | `127.0.0.1:5433` | `db:5432` |

Порты привязаны только к `127.0.0.1`; адрес `localhost:5173` используется лишь при запуске Vite через `npm run dev`. Пароль БД `crypto_dev_only` в Compose и `.env.example` предназначен **только для этой локальной БД**, не даёт доступа к Render и не должен использоваться в публичном окружении. Данные хранятся в Docker volume `crypto_education_pgdata`; схема создаётся API автоматически при первом старте.

### Переменные окружения и зависимости

Для локальной проверки через Docker переменные задавать **не нужно**. `.env.example` перечисляет параметры для других режимов; реальный `.env` игнорируется Git и Docker-сборкой. Не добавляй в репозиторий токены, ключи или производственные пароли.

| Переменная | Где нужна | Назначение |
| --- | --- | --- |
| `PORT` | API; в Compose `4100` | HTTP-порт приложения. |
| `NODE_ENV` | API; в Compose по умолчанию `development` | При `production` запуск без `MAX_BOT_TOKEN` запрещён. |
| `DATABASE_URL` | API; в Compose уже задан внутренний адрес БД | PostgreSQL для прогресса, маршрута и симуляций; обязателен в production с MAX. |
| `MAX_BOT_TOKEN` | Только сервер, когда нужна интеграция с MAX | Токен конкретного бота для входа пользователя, ответов и webhook; в локальном демо пустой. |
| `MAX_BOT_PUBLIC_URL` | Бот вне Render | Публичный HTTPS-адрес сервиса, по которому MAX доставит события webhook. |
| `RENDER_EXTERNAL_URL` | Render | Альтернативный публичный HTTPS-адрес для webhook; Render обычно задаёт его автоматически. |

Compose также фиксирует для **локальной** БД `POSTGRES_DB=crypto_education`, `POSTGRES_USER=crypto`, `POSTGRES_PASSWORD=crypto_dev_only`. Помимо Docker-образов Node.js 22 и PostgreSQL 17, для основного локального сценария не требуются внешние сервисы. Раздел «Рынок» обращается к публичным провайдерам котировок без API-ключей; при их недоступности показывает помеченный устаревшим локальный снимок. Реальная интеграция с MAX требует отдельного бота, его токена и публичного HTTPS-адреса: `localhost` не подходит для входа из MAX и webhook.

### Тестовые данные и сценарий проверки

Отдельный импорт данных и тестовые учётные записи не нужны. В приложении уже есть четыре курса по пять уроков, тесты, учебные кейсы, пять исторических сценариев и демонстрационные новости. Новая локальная БД начинает с пустым прогрессом; действия проверяющего сохраняются в ней. В симуляторе выдаются только виртуальные `100 000 ₽` — реальных сделок и платежей нет.

1. Открой http://localhost:4100. На главной должен быть учебный маршрут и кнопка его открытия; разделы доступны из нижнего меню.
2. Перейди в **Учиться → Криптовалюты**, открой урок «Криптовалюта — цифровой актив», пролистай экраны и ответь на итоговый тест. При ошибке посмотри разбор и пройди тест повторно. После успешного прохождения вернись в профиль или маршрут: урок должен учитываться в прогрессе.
3. Перейди в **Практика → Глобальный шок и восстановление**. Открой сценарий, запусти симуляцию, поставь её на паузу и возобнови, попробуй виртуальную покупку/продажу и посмотри итоговый разбор. Сценарий длится около шести минут активного времени; новости и будущие цены не раскрываются заранее.
4. Перейди в **Безопасность**, открой кейс и отправь решение. В **Рынке** проверь котировки и новости; при отсутствии сети котировки могут быть помечены как устаревшие.
5. Для проверки сохранения состояния выполни `docker compose restart app`, дождись статуса `healthy` в `docker compose ps` и обнови страницу: прогресс в PostgreSQL должен остаться. Это проверяет перезапуск приложения, не удаляя БД.

Локально бот MAX не подключён — это ожидаемо. Основной сценарий внутри MAX проверяется отдельно на опубликованной HTTPS-версии, а не по `localhost`. При токене приложение проверяет подписанные данные запуска на сервере; вне MAX показывает экран входа через бота. Docker-образ можно развернуть с теми же серверными переменными и публичным HTTPS, но для проверки локальной сборки это не требуется.

### Логи, остановка и типовые ошибки

- Логи и состояние: `docker compose logs --tail=100 app db` и `docker compose ps`. Если Docker daemon недоступен — запусти Docker Desktop и повтори команду.
- Если порт `4100` или `5433` занят, освободи его либо измени **левый** порт в `compose.yaml` и используй новый адрес в браузере. Не меняй внутренний `db:5432` в `DATABASE_URL` без необходимости.
- Если `app` не становится `healthy`, сначала проверь, что `db` стал `healthy`, затем прочитай логи. При случайно заданном `NODE_ENV=production` без `MAX_BOT_TOKEN` API намеренно не стартует; для локального демо убери эту переменную или задай `development`.
- Если вместо актуальной цены виден «последний локальный снимок», недоступен внешний поставщик котировок; уроки, кейсы и историческая практика от него не зависят.
- Остановка: `docker compose down`. Повторный запуск: `docker compose up --build --wait` (или `docker compose up --wait`, если код не менялся). Volume с прогрессом сохраняется. **Не используй `docker compose down -v`**, если хочешь сохранить результаты проверки.

## Работающая версия и развёртывание в MAX

Работающий бот для проверки: [Finspace в MAX](https://max.ru/t620_hakaton_max_bot). Открой ссылку в MAX, запусти бота и перейди в мини-приложение через его кнопку. Затем проверь маршрут, урок с тестом, практику и сохранение прогресса. Локальный Docker-запуск выше — отдельная демо-проверка без входа через MAX.

Для собственного развёртывания:

1. Создай бота в панели MAX и получи **токен именно бота**. Не подставляй вместо него токен команды хакатона со скриншота: его назначение нужно уточнить отдельно.
2. Размести приложение как Node.js Web Service с PostgreSQL и HTTPS. Для Render: сборка `npm ci && npm run build`, запуск `npm run start`; переменные окружения `NODE_ENV=production`, `DATABASE_URL` и `MAX_BOT_TOKEN`. В репозиторий токены не добавлять.
3. Укажи публичный адрес сервиса вида `https://<service>.onrender.com` в настройках мини-приложения бота. Проверь `/api/v1/health` и открытие через кнопку бота.

При заданном `MAX_BOT_TOKEN` API проверяет подписанные данные запуска MAX и требует выданную сессию для пользовательских запросов. Вне MAX показывает экран с просьбой открыть приложение через бота. Без токена остаётся локальный демо-режим. Для сохранения прогресса в production при MAX-входе `DATABASE_URL` обязателен. Данные карьерного теста также сохраняются в PostgreSQL.

## Запуск с PostgreSQL

1. Запусти Docker Desktop.
2. Подними базу:

```powershell
docker compose up -d db
```

3. Скопируй `.env.example` в `.env` или задай переменные в текущем терминале:

```powershell
$env:DATABASE_URL = "postgresql://crypto:crypto_dev_only@127.0.0.1:5433/crypto_education"
npm run dev
```

При подключении API автоматически применяет необходимые SQL-миграции из `apps/api/migrations`. Сессии Market Replay и сделки восстанавливаются после перезапуска; активная сессия открывается на паузе, чтобы время не прошло без пользователя.

Локальный пароль из `compose.yaml` предназначен только для разработки.

## Команды чат-бота MAX

Бот поддерживает `/start`, `/route`, `/progress` и `/help`. Прогресс берётся из того же аккаунта MAX, что и в мини-приложении; кнопки открывают маршрут, профиль или следующую остановку. Личные данные показываются только в диалоге с ботом.

При запуске с `MAX_BOT_TOKEN` и публичным HTTPS-адресом сервер регистрирует команды и webhook `/api/v1/bot/webhook`. На Render адрес берётся из `RENDER_EXTERNAL_URL`; для другого хостинга задайте `MAX_BOT_PUBLIC_URL`. Секрет webhook вычисляется из токена и проверяется перед обработкой события. Не публикуйте токен. При ошибке настройки смотрите сообщения `[bot]` в логах; повторная регистрация выполняется при перезапуске.

Для проверки после развёртывания отправьте боту `/start`, затем `/route` и `/progress`, проверьте переходы кнопок. Без токена и публичного HTTPS-адреса локально подключение к MAX не выполняется.

## Проверка собственного API

Полное описание методов и схем: [OpenAPI 3.0.3](documentation/openapi.yaml). Последовательность проверок, роли, параметры, ожидаемые ответы и встроенные тестовые данные: [DATA-API.yaml](documentation/DATA-API.yaml). Публичный HTTPS-адрес API — `https://crypto-max.onrender.com/api/v1`. Он работает параллельно с ботом MAX; сервис на бесплатном тарифе Render может просыпаться после простоя.

Для API-проверки не нужен аккаунт MAX или общий тестовый пароль: публичный `POST /auth/guest` создаёт **отдельного** гостя и возвращает подписанную сессию. Например, в PowerShell:

```powershell
$apiBase = 'https://crypto-max.onrender.com/api/v1'
Invoke-RestMethod "$apiBase/health"
$testSession = Invoke-RestMethod -Method Post "$apiBase/auth/guest" -ContentType 'application/json' -Body '{}'
$testHeaders = @{ Authorization = "Bearer $($testSession.accessToken)" }
Invoke-RestMethod "$apiBase/courses" -Headers $testHeaders
Invoke-RestMethod "$apiBase/route" -Headers $testHeaders
Invoke-RestMethod "$apiBase/career" -Headers $testHeaders
```

Сохраняй `$testSession` только в своей консоли: её `accessToken` даёт доступ к прогрессу созданного гостя. Для повторного входа передай этот Bearer в `POST /auth/guest`; без него создастся новый пользователь с пустым прогрессом. В Git не хранятся рабочие токены, пароли или статические тестовые учётные записи. В Docker-демо на `localhost:4100` Bearer не нужен, а `/auth/guest` не настроен.
